### 原始需求复述
我们要做一款轻量级 Web 数据库管理工具 MVP。核心范围 = SQL 客户端 + AI 自然语言生成 SQL（不做完整克隆、不做前端原型）。已确认：Web 应用形态；第一版支持 MySQL + PostgreSQL；AI 接入 OpenAI 兼容接口且可配置；默认技术栈为前端 Vite+React+MUI+Tailwind、后端 Node+Express。核心定位：管理多个数据库连接、SQL 编辑器执行与结果表格展示、AI 面板结合表结构生成 SQL 并可一键回填、安全上 AI 生成 SQL 仅建议且须用户确认执行、连接密码本地加密存储。

---

## 1. 产品目标

打造一款轻量级 Web 版数据库管理工具 MVP，帮助开发者和数据分析师通过浏览器集中管理 MySQL / PostgreSQL 连接、编写并执行 SQL、并以自然语言对话方式由 AI 辅助生成 SQL，从而降低数据库操作门槛、提升取数与分析效率；同时通过「AI 生成 SQL 仅作建议、必须用户确认才执行」与「连接密码本地加密存储」两项机制，在易用性与安全性之间取得平衡，为后续扩展更多数据库类型与高级 AI 能力打下基础。

---

## 2. 用户故事

1. **作为后端开发**，我希望在浏览器中保存并快速切换多个数据库连接，以便不必每次手动输入主机/端口/账号等连接信息。
2. **作为数据分析师**，我希望在 SQL 编辑器里编写并一键执行 SQL，并以表格形式查看查询结果（含耗时与行数），以便高效完成取数任务。
3. **作为不熟悉 SQL 的业务 / 运营人员**，我希望在 AI 面板用自然语言描述需求（如"查最近 7 天注册的用户"），系统结合当前库表结构生成 SQL 并一键回填编辑器，以便我无需手写 SQL 也能取数。
4. **作为安全负责人**，我希望连接密码以加密方式本地存储、且 AI 生成的 SQL 仅作为建议、必须由我手动确认后才执行，以便降低凭据泄露与误执行风险。
5. **作为团队用户**，我希望在配置中灵活设置 AI 接口（base URL + API Key + 模型名，兼容 GPT / 通义 / Ollama 等），以便在不同环境下使用合适的模型。

## 3. 需求池

### P0 — 必须（MVP 上线门槛）

**P0-1 数据库连接管理**
- 描述：支持新增 / 编辑 / 删除 / 列表展示数据库连接；保存连接配置（类型 MySQL|PostgreSQL、主机、端口、库名、用户名、密码）。
- 验收标准：
  - 能成功新增连接并在列表中展示；
  - 提供「测试连接」按钮，返回成功或明确失败原因；
  - 能从列表选中某连接进入 SQL 工作台。

**P0-2 SQL 编辑器与执行**
- 描述：在 SQL 工作台提供 SQL 编辑器，支持执行整段或选中 SQL，结果以表格展示，并显示执行耗时与影响/返回行数。
- 验收标准：
  - 执行 SELECT 返回正确列与行；
  - 错误 SQL 给出明确错误提示且不崩溃；
  - 支持多选执行（按选中文本执行，否则执行全部）。

**P0-3 AI 自然语言生成 SQL**
- 描述：在 AI 面板输入自然语言需求，后端拉取当前所选连接的库表结构作为上下文，调用 OpenAI 兼容接口生成 SQL 并返回。
- 验收标准：
  - 针对合理需求返回可执行的合法 SQL；
  - 表结构上下文随所选连接 / 数据库变化而更新；
  - 生成结果支持「一键回填」到 SQL 编辑器。

**P0-4 连接密码加密存储**
- 描述：连接密码在落盘前加密，读取时解密（具体加密方案见待确认问题）。
- 验收标准：
  - 存储介质中密码不以明文出现；
  - 应用启动后可正常解密并建立连接。

**P0-5 AI 生成 SQL 须用户确认执行**
- 描述：AI 生成的 SQL 仅回填到编辑器，绝不自动执行；执行必须由用户主动触发。
- 验收标准：
  - AI 返回 SQL 后页面不会自动运行；
  - 用户点击「执行」才真正发往数据库。

### P1 — 重要（提升可用性，建议首版包含）

**P1-1 执行历史记录**：保存最近执行的 SQL 与状态摘要，可点击重新载入到编辑器。
**P1-2 结果表格增强**：支持按列排序、导出 CSV。
**P1-3 AI 接口配置页**：图形化配置 base URL / API Key / 模型名，并提供连通性测试。
**P1-4 友好错误处理**：连接失败、SQL 错误、AI 调用失败均有清晰提示与重试入口。
**P1-5 结果集行数限制**：大数据量结果默认 LIMIT（如 1000 行）防止前端卡顿。

### P2 — 可选（后续迭代）

**P2-1** 多语句结果以多标签分别展示。
**P2-2** 左侧 schema 树形浏览（库 → 表 → 字段 / 类型 / 注释）。
**P2-3** SQL 语法高亮与基础自动补全。
**P2-4** 暗色主题切换。
**P2-5** 连接配置导入 / 导出为 JSON。

### 4.2 SQL 工作台页（路由 `/workbench`）

功能：左侧连接/表结构、中间编辑器+结果、右侧 AI 面板。

```
┌──────────────────────────────────────────────────────────────────────┐
│  DBClient  ▸  生产库(MySQL)                          [⚙][退出连接]      │
├────────────┬───────────────────────────────┬─────────────────────────┤
│ 连接/结构   │  SQL 编辑器                    │  AI 助手                │
│ ─────────   │ ┌─────────────────────────┐   │  ┌───────────────────┐  │
│ ▸ 生产库     │ │ SELECT * FROM users     │   │  │ 输入需求…          │  │
│   ▸ users   │ │ WHERE created_at >      │   │  │ [发送]             │  │
│     id PK   │ │   DATE_SUB(NOW(),7)     │   │  └───────────────────┘  │
│     name    │ └─────────────────────────┘   │  ─ 生成结果 ─           │  │
│     email   │ [▶ 执行]  [格式化]  [清空]      │  SELECT ... FROM ...   │
│   ▸ orders  │ ───────────────────────────    │  [回填编辑器][复制]     │
│             │  结果表格                        │                        │
│             │ ┌────┬────────┬────────┬─────┐ │                        │
│             │ │ id │ name   │ email  │ ... │ │                        │
│             │ ├────┼────────┼────────┼─────┤ │                        │
│             │ │ 1  │ 张三   │ a@x.com│ ... │ │                        │
│             │ └────┴────────┴────────┴─────┘ │                        │
│             │ 共 1000 行 · 耗时 23ms          │                        │
├────────────┴───────────────────────────────┴─────────────────────────┤
└──────────────────────────────────────────────────────────────────────┘
```

组件说明：
- **左侧栏**：当前连接下的库 / 表 / 字段树（P2-2 增强；MVP 至少展示表名列表）。
- **中间区**：SQL 编辑器（MVP 可用轻量编辑器组件，P2-3 再做高亮/补全）；`执行` 按钮触发查询；下方结果表格展示列与行、行数与耗时。
- **右侧 AI 面板**：自然语言输入框 + 发送；生成结果展示区；`回填编辑器` 将 SQL 写入中间编辑器（**不自动执行**，满足 P0-5）；`复制` 便捷拷贝。

### 4.3 AI 接口配置页（路由 `/settings` 或弹窗）

图形化表单：Base URL、API Key、模型名（如 `gpt-4o` / `qwen-plus` / `ollama/llama3`），`测试连通性` 按钮，`保存`。配置持久化到后端（加密存储 Key 见待确认问题）。

## 5. 待确认问题（Open Questions）

1. **密码加密方案**：采用何种加密（如 AES-256 + 主密钥）？主密钥存放位置（环境变量 / 系统密钥库 / 首次启动生成并落盘）？是否需要密钥轮换？
2. **AI 上下文范围与脱敏**：发送给模型的是仅表结构（DDL / 列名 / 注释），还是也包含少量样本数据行？若含样本是否需要脱敏？表结构获取用 `information_schema` 还是 `SHOW` 类命令？
3. **连接配置存储位置与隔离**：配置存后端本地文件（JSON / SQLite）还是浏览器 localStorage？若后端多人共用，连接 / AI Key 如何按用户隔离（是否需要登录体系）？MVP 是否先按单机单用户处理？
4. **AI 接口配置归属**：全局一份 AI 配置，还是每个连接可独立覆盖模型 / Key？默认模型与超时如何设定？
5. **结果集行数上限与分页**：默认 LIMIT 多少（建议 1000）？是否支持「下一页」翻页查询，还是超出即截断并提示？

---

## 6. 范围边界（明确不做）

- 不做完整克隆与全部功能（如数据导入导出全链路、可视化建模、权限 RBAC）。
- 不做前端高保真原型（以可运行 MVP 为准）。
- 第一版不支持 MySQL / PostgreSQL 之外的数据库（Oracle / SQL Server / SQLite 等留待后续）。
- 不做 AI 自动执行写操作（INSERT/UPDATE/DELETE/DDL）的默认放行，P0-5 强制人工确认。
